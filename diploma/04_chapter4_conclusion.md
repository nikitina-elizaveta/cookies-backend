# ГЛАВА 4. ТЕСТИРОВАНИЕ И ЭКСПЛУАТАЦИЯ

## 4.1. Методика тестирования

Тестирование разработанной системы проводилось комплексно и включало следующие виды проверок:

### Виды тестирования

1. **Модульное тестирование (Unit Testing)**:
   - Проверка отдельных функций и методов;
   - Валидация моделей Pydantic;
   - Тестирование SQL-запросов.

2. **Интеграционное тестирование**:
   - Проверка взаимодействия между компонентами;
   - Тестирование API endpoints;
   - Проверка работы с базой данных.

3. **Системное тестирование**:
   - Проверка полного цикла работы системы;
   - Оформление заказа от выбора товара до подтверждения;
   - Работа административной панели.

4. **Приёмочное тестирование**:
   - Соответствие требованиям технического задания;
   - Проверка юзабилити интерфейса.

### Инструменты тестирования

Для тестирования использовались:

- **Postman / Insomnia**: Для ручного тестирования API endpoints;
- **Swagger UI**: Автоматически сгенерированная документация FastAPI для проверки запросов;
- **Браузерные DevTools**: Для отладки frontend-части;
- **Python logging**: Для анализа работы сервера.

### Тестовые данные

Для проведения тестов была подготовлена база данных со следующими характеристиками:

- **Количество товаров**: 50+ кондитерских изделий;
- **Количество категорий**: 4 основные категории;

- **Тестовые заказы**: 100+ записей о продажах.

### Известные ограничения

В ходе тестирования были выявлены следующие ограничения системы:

1. **Отсутствие пагинации**: При большом количестве товаров (>1000) ответ может быть слишком большим.
   
   *Рекомендация*: Добавить параметры limit/offset для endpoint /api/products.

2. **Простая аутентификация**: Токен не истекает, что снижает безопасность.
   
   *Рекомендация*: Внедрить JWT с expiration time.

3. **Отсутствие кеширования**: Каждый запрос выполняет SQL-запрос к базе.
   
   *Рекомендация*: Добавить Redis для кеширования популярных запросов.

4. **SQLite ограничения**: При высокой конкурентной нагрузке возможны блокировки файла.
   
   *Рекомендация*: Для production использовать PostgreSQL.

## 4.3. Руководство пользователя

### Для клиентов магазина

#### Просмотр каталога товаров

1. Откройте главную страницу веб-приложения.
2. Вы увидите список всех доступных кондитерских изделий.
3. Используйте панель фильтров слева для уточнения поиска:
   - **Праздник**: Выберите событие, к которому подбираете сладости;
   - **Ингредиенты**: Укажите предпочтения по составу;
   - **Диетические ограничения**: Отметьте нужные параметры (без орехов, без глютена, веган);
4. Для сортировки по цене используйте выпадающий список "Сортировка".

#### Добавление товаров в корзину

1. Нажмите кнопку "В корзину" на карточке товара.
2. Количество товаров можно изменить в корзине.
3. Итоговая сумма обновляется автоматически.

#### Оформление заказа

1. Перейдите в корзину.
2. Проверьте состав заказа и итоговую сумму.
3. Нажмите кнопку "Оформить заказ".
4. Заполните форму:
   - **Имя**: Ваше имя;
   - **Телефон**: Контактный номер для связи;
   - **Комментарий**: Пожелания по доставке или оформлению (необязательно).
5. Нажмите "Подтвердить заказ".
6. Вы получите подтверждение с номером заказа.

### Для администраторов

#### Вход в систему

1. Перейдите на страницу `/admin`.
2. Введите учётные данные:
   - **Логин**: admin
   - **Пароль**: admin123
3. Нажмите "Войти".
4. Токен будет сохранён для последующих запросов.

#### Просмотр заказов

1. В административной панели выберите раздел "Заказы".
2. Вы увидите список всех заказов с датой, именем клиента и суммой.
3. Для просмотра деталей нажмите на номер заказа.
4. В деталях отображаются:
   - Информация о клиенте;
   - Состав заказа;
   - Комментарий.

#### Работа с аналитикой

Административная панель предоставляет следующие отчёты:

**1. Популярные товары**

- Показывает топ-10 самых продаваемых товаров.
- Можно указать период (дата начала и конца).
- Данные отображаются в виде таблицы.

**2. Продажи по группам ингредиентов**

- Анализирует выручку по типам ингредиентов (шоколад, фрукты, орехи и т.д.).
- Автоматически выбирает последний месяц с продажами.
- Можно указать конкретный год и месяц.

**3. Продажи по праздникам**

- Показывает, какая продукция наиболее востребована к определённому событию.
- Помогает планировать ассортимент к сезону.

**4. Динамика по диетическим характеристикам**

- Отслеживает спрос на продукцию с особыми свойствами (веган, без глютена и т.д.).
- Группировка по месяцам показывает тренды.

**5. Статистика фильтров**

- Показывает, какие фильтры используют покупатели.
- Помогает оптимизировать навигацию по каталогу.

**6. Непродуваемые товары**

- Выявляет товары с низким спросом.
- Помогает принять решение об исключении из ассортимента.

#### Построение графиков

Данные аналитики можно экспортировать и визуализировать:

1. Скопируйте JSON-ответ из API.
2. Используйте инструменты визуализации (Chart.js, D3.js, Excel).
3. Примеры типов графиков:
   - **Столбчатая диаграмма**: Популярные товары;
   - **Круговая диаграмма**: Продажи по праздникам;
   - **Линейный график**: Динамика продаж по месяцам.

## Основные результаты работы

1. **Проведён анализ предметной области**:
   - Изучены бизнес-процессы магазина кондитерских изделий;
   - Выявлены проблемы традиционных методов учёта;
   - Сформулированы требования к системе.

2. **Спроектирована структура базы данных**:
   - Разработана нормализованная схема из 12 таблиц;
   - Реализованы связи многие-ко-многим для состава продукции и привязки к праздникам;
   - Создана таблица FilterEvents для отслеживания пользовательской активности.
